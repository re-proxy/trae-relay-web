# Trae Relay Web

将 Trae 国内个人账号和公共 SaaS 企业账号提供为 OpenAI 兼容 API，使用 Go 后端和内嵌中文管理页面，适合通过 Docker 部署在内网服务器。

**基于 [Santonin205/Trae-Relay](https://github.com/Santonin205/Trae-Relay)（Windows 原生项目，参考版本 0.21.0）移植。感谢原作者提供的上游协议、登录和 API 转换实现。** 本仓库是独立的 Web / Linux 实现。

支持 Chat Completions、Responses、SSE、图片与工具调用；管理页面提供账号启停、重命名、删除、模型偏好、多 API Key 和使用记录；可逐个验证账号连通性、查询个人剩余积分与企业套餐额度。

## Docker 部署

准备好 Docker Engine 和 Compose v2，确认服务器的 **8317/TCP** 可从内网访问。默认同时配置容器监听 `0.0.0.0:8317`、宿主映射 `0.0.0.0:8317:8317`，可直接通过服务器内网 IP 使用。

### 1. 获取项目

```sh
git clone https://github.com/re-proxy/trae-relay-web.git
cd trae-relay-web
```

### 2. 生成首次配置

```sh
sh scripts/init-env.sh
```

脚本使用本机 OpenSSL 生成 `.env`，只包含两项：

| 配置 | 用途 |
| --- | --- |
| `RELAY_ADMIN_PASSWORD` | 登录管理页面的密码 |
| `RELAY_MASTER_KEY` | 加密保存账号凭据的主密钥，生成后必须保留 |

打开 `.env` 查看管理密码并妥善保存。脚本不会覆盖已存在的 `.env`；升级时跳过此步骤，继续使用原文件。

没有 OpenSSL 或使用 NAS 文件管理器时，也可把 `.env.example` 复制为 `.env` 后手动填写：管理密码不能为空，建议使用随机长密码；主密钥必须是 **32 随机字节的标准 Base64**。可使用容器内置命令生成主密钥，无需在宿主机安装工具：

```sh
cp .env.example .env
docker compose run --rm --no-deps --build relay keygen
```

把输出的随机值填入 `.env` 的 `RELAY_MASTER_KEY`，再设置一个不同的 `RELAY_ADMIN_PASSWORD`。这一步仅生成密钥并退出，不会发起账号登录。已有 `.env` 时不要重复复制或更换主密钥。

### 3. 启动服务

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=50 relay
```

浏览器打开 **`http://服务器内网IP:8317`**，例如 `http://192.168.1.10:8317`，使用 `.env` 中的 `RELAY_ADMIN_PASSWORD` 登录。

`0.0.0.0` 是监听地址，浏览器请填写服务器实际 IP。服务器本机可使用 `http://127.0.0.1:8317`。健康检查：

```sh
curl http://127.0.0.1:8317/health
# 正常返回 {"status":"ok"}
```

### 管理界面

控制台按任务分成四个页面，各有独立地址，可直接收藏或从别处链接过去：

| 页面 | 地址 | 内容 |
| --- | --- | --- |
| 账号 | `/`（也可 `/accounts`） | 账号列表、连通性、剩余积分、每日签到 |
| 模型 | `/models` | 上游模型目录与计费倍率，搜索、筛选、别名、思考档位、启用与 Max |
| API 接入 | `/keys`（也可 `/access`） | Base URL、创建与撤销 API Key |
| 使用记录 | `/usage` | 最近 500 次请求的模型、token、状态与耗时 |

登录态对所有页面有效，登录一次即可；未登录时任何地址都会显示登录框，登录后回到该地址。反向代理需要保留这些路径前缀。

### 4. 添加账号并连接客户端

1. 管理页点击 **添加账号**，打开生成的 Trae 官方登录链接。
2. 在浏览器完成登录。如果跳转到 `http://127.0.0.1:<随机端口>/authorize?...` 后显示无法访问，复制地址栏中的**完整回调 URL**，回到管理页粘贴提交。
3. 保存成功后点击该账号的 **启用**，再点击 **刷新模型目录**。
4. 在 **API 接入** 页填写客户端名称，点击 **创建 API Key**，立即复制保存；新密钥只显示一次。
5. 在 OpenAI 兼容客户端填写：

| 客户端配置 | 示例 |
| --- | --- |
| Base URL | 「API 接入」页按你当前访问的地址显示，形如 `http://192.168.1.10:8317/v1`；配置域名或反向代理后自动显示该域名，无需改配置 |
| API Key | 管理页生成的 API Key；不是管理密码 |
| Model | 模型列表中的实际 ID 或你设置的别名 |

```sh
curl http://192.168.1.10:8317/v1/models \
  -H "Authorization: Bearer YOUR_API_KEY"
```

远程授权沿用原项目支持的本机回调格式，通过粘贴提交到服务器，不要求容器读取宿主凭据。**官方页面是否在没有本机监听器时仍留下完整回调 URL，尚未用真实账号实测。** 如果页面没有进入带参数的回调地址，请重新创建登录会话，不要自行修改回调参数。回调 URL 含一次性授权信息，只提交到自己的管理页。每次提交都会消费该会话，失败后需重新添加。

## 账号检查、余额与多密钥

- **验证连通性**：账号卡片上的按钮会刷新必要凭据、验证官方用户身份并访问模型目录；显示检查时间、延迟、模型数量或失败原因。不发送聊天请求，也不切换当前启用账号。验证通过表示身份与目录可访问，不保证所有模型都可生成。
- **查询余额**：个人账号显示官方接口报告的剩余积分和查询时间；企业账号支持时显示套餐金额额度，实际消费和剩余额度通过卡片上的官方控制台链接查看。查询失败会明确显示失败，不将未知余额显示为 0。余额按需手动刷新。
- **每日签到**：个人账号每天自动领取签到积分，默认在服务端本地时间 10:00 之后执行一次；也可在账号卡片上手动「立即签到」或关闭自动签到。签到结果（已入账 / 已签到 / 确认中 / 失败）直接显示在卡片上，入账后自动刷新积分。企业账号不参与签到。
- **多个 API Key**：为不同客户端分别创建、命名、停用、启用或撤销，最多保存 32 个。完整密钥只在创建时显示，列表仅显示末六位。升级前的旧 API Key 继续有效，支持独立管理；停用或撤销不影响其他客户端。

## 模型与偏好

模型目录采用卡片展示，可按名称、ID、提供方搜索，也可筛选已启用、图片、思考和 Max 模型。每张卡片可分别设置 API 别名、思考档位、Max 模式和启用状态；修改后点击“保存偏好”。搜索和筛选会保留当前未保存的编辑。

计费倍率直接解析原项目使用的上游 `display_contact_config`：显示基础倍率，以及目录提供的会员、活动和活动会员倍率；闲时活动显示北京时间适用窗口。切换 Max 时展示对应 Max 档位的倍率，没有数据时显示“上游未提供”，不会按 0 或普通档位价格处理。会员/活动价格需满足上游条件，本页不推算当前账号一定享有的折扣或实际费用。刷新模型目录可同步最新目录倍率。

## 数据与升级

账号凭据、API Key、模型设置和最近 500 条使用记录加密保存在 Docker 的 `relay-data` volume。请分别备份 **数据 volume** 与 **原 `.env`**；重新生成主密钥后，已有数据将无法解密。

升级保留 `.env` 和 volume，执行：

```sh
git pull --ff-only
docker compose up -d --build
```

停止服务用 `docker compose down`。不要在需要保留账号时使用 `docker compose down -v`，它会删除数据 volume。同一份数据仅运行一个服务实例。

## 常见问题

| 问题 | 检查方法 |
| --- | --- |
| 内网其他电脑打不开 | 使用服务器实际内网 IP，检查 8317/TCP 的主机防火墙或网络规则；Compose 默认已绑定所有 IPv4 接口 |
| 启动失败 | 查看 `docker compose logs --tail=100 relay`；确认 `.env` 两项已填写，主密钥格式正确，端口未被占用 |
| 管理页进不去 | 使用 `.env` 的管理密码，不是 API Key；重启后需重新登录 |
| API 返回 401 | 先确认使用的是管理页生成的 API Key（Bearer 或 X-API-Key）；若 message 来自上游，表示账号凭据过期且刷新失败，需要重新登录账号 |
| API 返回 429 | 上游账号限流（code 4011 等），等待后重试或改用其他账号；本项目不重试限流请求 |
| API 返回 403 | 上游额度不足（code 1005），在官方控制台确认套餐或积分 |
| API 返回 502 | 上游失败且无可用状态码，看响应里的 code：`upstream_first_event_timeout` 表示上游迟迟未开始输出 |
| API 返回 503 | `no_enabled_account` 表示没有启用账号；`account_concurrency_limit` 表示所有账号并发已满且排队超时，可提高 `RELAY_MAX_CONCURRENT` 或 `RELAY_ACCOUNT_QUEUE_MS` |
| 修改 `.env` 后未生效 | 执行 `docker compose up -d --force-recreate` |
| 想改宿主端口 | 直接编辑 Compose 的 `ports`，例如 `0.0.0.0:9000:8317`，客户端相应使用 9000 |
| HTTPS 反向代理或模型高级设置 | 查看 [高级配置与兼容说明](docs/ADVANCED.md) |

## 兼容范围与验证状态

仅支持国内个人与公共 SaaS 企业账号。支持手动查询个人剩余积分与个人账号每日自动签到；不支持国际版、企业私有部署，以及严格 JSON Schema、托管搜索、音频等接口。Responses 会话仅在内存缓存，重启后需要重新传入历史。完整范围见 [API 与高级说明](docs/ADVANCED.md)。

Windows 与 WSL Ubuntu 的构建、26 项离线测试及 race 检查、无凭据启动、SIGTERM 和重启恢复已验证。**Docker 镜像运行与真实账号的登录、刷新、生成尚未实测**，详见 [验证记录](VALIDATION.md)。
